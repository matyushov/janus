Roadmap and releases

Where janus is going, version by version.

Order matters; dates are not promised. A version ships when its exit criteria are met, and each one has criteria that can be checked. The project is a one-person open source effort, so the plan favours a few things done properly over many things half done.

Versioning

Three numbers, on purpose

janus is pre-1.0: minor versions may change behaviour, and every change is listed in the release notes on GitHub Releases. Three version numbers exist and move independently.

NumberWhere you see itWhat it means
Release version 0.x.ythe workspace version, the git tag v0.x.yThe software as a whole. Semantic Versioning without exceptions from 1.0.
C ABI versionjanus_client_abi_version(), currently 1Changes only when the C interface of libjanus breaks.
Wire protocol revisionproto_rev in the receiver's reply, currently 2The gRPC contract between the client and the receiver. Additions stay compatible; a bump means an older peer may be refused.

Releases are source-only until binaries can be signed (v0.2.0): an unsigned command-line binary downloaded in a browser is quarantined by macOS, and it is not something to hand to users. Every release is marked pre-release until 1.0.

Versions

From a working core to a stable 1.0

v0.1.0

Preview

current state

A working core, proven with the hardest client, built from source.

What it contains

  • An SMB 3.1.1 server in Rust: signing required, NTLMv2, no guests, durable handles V2, lease V2, interim STATUS_PENDING and CANCEL, Apple extensions, F_FULLFSYNC.
  • macOS Time Machine as the first verified client: full and incremental backups, file restore, a killed client and receiver outages up to about two minutes survived.
  • A receiver over gRPC with mutual TLS 1.3, one store and quota per machine, zstd on the wire.
  • A write-ahead journal with an honest fsync and background upload.
  • An embeddable client: a C library with eleven functions, a header-only C++ wrapper, a CMake package, five examples.
  • Command-line control, live status and logs, this site.

Known limits. Tested on macOS 26 only. An outage longer than about two minutes aborts a Time Machine run (Time Machine's own limit). Linux and Windows SMB clients are not supported. There is no installer or background service; the daemon runs from a shell. No certificate revocation. No external security review.

v0.2.0

Installable and trustworthy

next

A stranger can install it from the documentation, and has reasons to trust it.

Scope

  • Packaging. A reproducible .deb for the receiver built in CI from a script in the repository. A documented, signed way to run the client on macOS: an unsigned command-line binary does not get the Local Network permission under launchd, so the answer is an app host with a stable signature or another route.
  • A Time Machine setup helper. tmutil setdestination stores the password with no access for the system's network authentication agent, so backupd cannot read it; the helper creates the keychain entry correctly and explains each step.
  • Certificate lifecycle. Enrolling a machine without hand-editing JSON, listing, expiry warnings and a real way to revoke a client.
  • Fail fast on a rejected certificate. A client whose certificate is refused currently retries for the whole two-minute patience before reporting an error; telling an authentication failure from an unreachable network makes it an immediate, clear error.
  • Hardening. Fuzz targets for the SMB codec and the authentication parsers running in CI, a dependency audit in CI, a written threat model.
  • Native launchd socket activation, receiver logs, an install guide.
  • Dogfooding. The maintainer's own Mac backs up through janus for several weeks before the tag.
Exit criteria. A fresh Mac and a fresh Linux server go from nothing to a completed Time Machine backup in under thirty minutes using only the documentation; the fuzzers ran for a meaningful time without a crash; revoking a client works.
v0.3.0

Recoverable

later

Getting a whole machine back, not just files.

Scope

  • Restore from macOS Recovery, verified end to end. The daemon runs in Recovery and the restore wizard lists the backups today; the path through Migration Assistant after a reinstall is not verified. Turn the lab procedure into documentation, or document exactly where the boundary is.
  • Credential delivery for Recovery without copying a private key by hand (short-lived credentials), if the threat model allows it; otherwise a documented manual procedure.
  • Resume after an interrupted backup. Measure what Time Machine does on the next run after a long outage; only if it starts over, build the metadata mirror that lets a backup survive longer outages.
  • Snapshot browsing on the server (a read-only mount of a snapshot), including how it interacts with encryption.
  • Encryption and key ownership. Decide and document who holds the key and what janus does and does not protect; no unspecified behaviour.
Exit criteria. A tested, written procedure restores a machine from an empty disk, or there is a documented list of what cannot be done and why.
v0.4.0

More clients

later

"Any SMB client" becomes a verified matrix.

Scope

  • Linux. Fix session setup for cifs.ko (it appears to send a bare NTLMSSP token where the server expects SPNEGO); verify the POSIX profile with cifs.ko and smbclient.
  • Windows. Verify the Windows profile with Explorer, robocopy and File History, including signing.
  • Client tests in CI. Linux cifs in a container at least, plus a documented manual matrix for macOS and Windows.
  • Byte-range locks and share modes, if a verified client needs them.
Exit criteria. A published client matrix in which every "works" is backed by a test or a recorded run.
v0.5.0

More backends

later

Object storage behind the same share.

Scope

  • S3-compatible storage (AWS S3, MinIO, Wasabi, R2, Ceph) behind the receiver. Time Machine's 256 MiB sparse bands make "one file, one object" impractical, so the choice between a chunked layout and multipart upload with server-side copy follows measurements: the write profile of the backup client first, then a prototype against MinIO.
  • Guidance for bucket policies: versioning and Object Lock conflict with Time Machine's thinning of old backups.
  • The backend interface is frozen and every backend must pass the same contract tests.
Exit criteria. A Time Machine backup completes to MinIO, and the costs and trade-offs are documented.
v1.0.0

Stable

goal

Promises that can be kept.

  • The C ABI is frozen and its compatibility policy is written down.
  • The wire protocol has a stated policy: what an old client and a new receiver may do.
  • Signed binaries for the supported platforms.
  • A structured security review (external if possible) and a clean fuzzing history.
  • Months of real use without data-loss reports, complete documentation, triaged issues.
  • From here on, Semantic Versioning without exceptions.
Not planned

What janus will not become

An iSCSI initiator or a kernel extension

Block devices need drivers the platform vendors gate and change; that is a different project.

A bundled Samba

The point is a small, strict SMB server written for this job, with nothing borrowed from a general-purpose one.

SMB on the network

A server-side SMB listener would undo the reason janus exists: SMB never leaves the client machine.

janus — a local SMB share backed by storage you control.
